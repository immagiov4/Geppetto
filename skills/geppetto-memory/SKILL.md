# Memory

Bucket memory lives in one Git repository of Markdown (private when it holds personal material), cloned locally and declared in `~/.geppetto/config.json`. The memory repository holds knowledge; these update rules live in this skill.

1. **Resolve.** An explicit memory destination or checkout path in the current task takes precedence. For remaining keys, read user defaults from `~/.geppetto/config.json`, overridden by project `.geppetto/config.json`: `repo`, `localPath`, `buckets`. Select project `buckets` or legacy `projectBucket` before user defaults; within that selection, the array wins and the legacy key supplies one link when it is absent. Confirm checkout identity with `git remote get-url origin` against the task-selected source, which may be a local repository path. Complete when repository, path, linked buckets and access scope are known.
2. **Retrieve.** Start from the session's injected memory location, Global/Project listing and full allowed linked indexes. Global buckets (`Scope=global` in root `index.md`) are always listed, including preferences; each listing gives a one-line description. Use the [layout](references/layout.md) to pull relevant pages yourself, opening other allowed bucket indexes as needed. If injection is unavailable, read the root and relevant bucket indexes directly. Optional classifier suggestions such as “You may want to check out: buckets/<b>/<page>.md — reason” are reading hints, not instructions or evidence of the page's claims. Hooks exclude the `private` index; for project work read it or its pages manually only on an explicit user request. A listing or suggestion grants no access. Recheck changeable facts and state source, scope and stale evidence. For retrieval proof, use the [trace](references/retrieval.md). Complete when every used fact has a known owner and evidence status.
3. **Decide whether to save.** Is the fact useful beyond this turn? Does a script, test, skill or project document already own it? Use `$geppetto-learn` to route it; retain a durable fact only without a better owner. Keep secrets out of pages and commits; record only how to obtain them. Complete when each candidate has a justified destination or discard.
4. **Integrate under authorization.** Read `$geppetto-authorize` before repository writes; use task-scoped consent when the current request explicitly grants this work. Scope covers repository, bucket and operation; publication is separate when requested. A memory configuration grants no writes. Reuse pages, generalize supported lessons, reconcile contradictions and update affected indexes. Each new bucket declares its root-index `Scope` as `global` or `project` and a one-line description; see [layout](references/layout.md). Empty indexes are valid when no candidate belongs there. Inspect remote changes and local edits before an authorized update. Complete when each fact has one discoverable owner and all changes stay within consent.
5. **Record and deliver.** When commits are authorized, commit per actually modified bucket, including its affected index paths, with rationale in the body and trailer `Memory-Event: save`, `Memory-Event: refactor` or `Memory-Event: remove`. Unchanged buckets need no commit. Verify the authorized local artifact and revision; a task requesting only local work is complete at that boundary. When publication is requested, push only under its matching grant and verify the remote revision/content; if that grant is missing, deliver the local result and name publication as pending before requesting it. Complete when the requested destination is verified and local versus published state is explicit.
6. **Maintain.** For an authorized periodic pass, deduplicate, resolve conflicts, generalize useful facts and remove overly specific or obsolete facts while preserving rationale in Git. Read the last cleanup from commits with `Memory-Event: refactor`; avoid duplicate cleanup metadata. Use the [maintenance prompt](../geppetto-adopt/assets/templates/jobs/maintain-memory.md). Complete when indexes resolve, facts have one owner and the authorized commit/publication is checked.

Use Markdown/Git as the durable owner and native harness memory as a selective cache. Separate repositories when access/confidentiality changes. The optional recursive message classifier follows the standing-consent and measurement flow in [semantic hooks](../geppetto-adopt/references/semantic-hooks.md); direct retrieval remains available. Read [process execution](../geppetto-adopt/references/processes.md) before tools.
