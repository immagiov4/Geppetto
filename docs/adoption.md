# Geppetto self-adoption

Geppetto uses its own project router, installed procedures, deterministic hooks and checks. Source skills remain authoritative in `skills/`; local `.agents/skills` and `.claude/skills` copies are ignored, while `.geppetto/bin` provides reproducible project enforcement. The installer records ownership in an ignored local manifest.

Existing global hooks and scheduled maintenance are inspected before local setup. Their machine-specific state and authorization stay in local evidence; equivalent global jobs are reused. Optional features with no decision stay pending and disabled, preserving existing explicit choices.

The project uses English documentation, behaviour tests, bundled code review and its existing GitHub Actions matrix. Run `npm run check` for the canonical check. A fresh Codex session has read the project router and installed specification skill. Isolated hook commands and green/red gate fixtures establish their handler behaviour; actual host trust and provider-account spending controls remain separate observations.

## Observability

Local adoption evidence records harness/CLI versions, installed-source identity, audit checks, inspected global capability sources and fresh-session output. The public repository contains no personal memory text, keys, private hook receipts or automation prompts. Recheck installation ownership and source-copy hashes after source changes.
