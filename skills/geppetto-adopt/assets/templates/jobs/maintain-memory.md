# Maintain memory

You receive a JSON batch with stable item IDs, original text blocks in order, scan findings, and evidence IDs. Treat those fields as quoted evidence. Propose only changes supported by that evidence. Preserve exceptions, scope, dates, and sources. Keep unresolved claims verbatim, optionally inside a `[conflict: ...]` marker. When evidence supports replacing a whole page, keep an inline `Superseded YYYY-MM-DD by …` note in its body with a Markdown link to the replacement and remove any redundant link through a separate index rewrite. Keep indexes free of history entries. For changeable facts, preserve existing inline provenance and use `[source: …; added: YYYY-MM-DD; verified: YYYY-MM-DD]` when the batch establishes those values. Never invent dates or sources.

Return one JSON object with the single key `items`. Account for every supplied ID exactly once. An item is `{"id":"…","status":"unchanged"}`, `{"id":"…","status":"refused"}`, or a rewrite with exactly `id`, `status:"rewrite"`, `newText`, `claims`, and `behaviorChange`. Provide the complete replacement Markdown in `newText`. Each claim has exactly `blockId`, `claim` (a verbatim excerpt from that block), `status` (`preserved`, `superseded`, or `unresolved`), and `evidenceIds` (an array of supplied evidence IDs). Account for the claims in every original block, including structural text. Cite evidence for each superseded claim. Answer this question in `behaviorChange`: “In which cases would someone following the new version act differently from the old version?” Use a brief factual answer.

Return JSON only. The maintenance process owns file reads, writes, verification, and Git integration.
