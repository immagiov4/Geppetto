# Adopt

Restructure what already works with the maintainer. Read [installation and script contracts](references/installation.md) before operating on files; read `$writing-for-agents` before changing instructions. Use [templates](assets/templates/AGENTS.md) as material to adapt, not as permission to replace existing rules.

1. **Probe.** Run `node <adopt>/scripts/audit.mjs --project <project> --json`. Inspect instruction/skill discovery, hooks, scheduling, plugins, memory, Node, Git, `gh` and review prerequisites for each target harness. Mark each capability present, absent or unverified. Complete when the capability table distinguishes observations from assumptions.
2. **Inventory.** Use the instruction-migration helper described in [installation](references/installation.md) to inventory every AGENTS/CLAUDE section. Classify routing, obligations, guidance to relocate and obsolete material; preserve content at its owner or record an approved drop. Inventory local skills, extra packs, docs, tests, CI, observability and host formatter/linter configuration. Complete when every section and pillar has a disposition and each vendored-path conflict is visible.
3. **Recommend.** Before the pillar table, tell the maintainer what the pack is for, in their language: the agent should improve the system on its own when friction recurs, choose the shape of the fix from the evidence rather than a fixed menu, and can do that only if the work stays visible. Name the five intents in the [router template](assets/templates/AGENTS.md). Then report pillars by harness, required or recommended status, evidence and reason. An equivalent existing implementation satisfies a pillar; Geppetto's principle skills still ship complete, because they are the scaffold learning stands on, not a replacement methodology. Complete when each row has a state and rationale, including missing capabilities and their existing-tool alternatives.
4. **Ask once.** Read [project choices](references/choices.md) after verifying equivalents. Use its [visible consent block](references/choices.md#approval-and-installation-messages) for one grouped round, reusing recorded answers; include memory bucket links, standing subscription signal learning (default yes), paid data/spending scope when relevant, and uncovered periodic learning, curation and memory maintenance. When the CLI is authenticated and subscription learning is accepted, run `learning-setup.mjs --project <project> --accept` to record its standing project grant and complete defaults. Preserve declines. Keep bundled review and feedback procedures, choosing a working verification runtime from the available CLIs, applications and harnesses through [installation](references/installation.md), or retain the owner's selected alternative. Complete when every relevant choice and accepted grant is recorded, with one actionable item per missing prerequisite.
5. **Install required pillars.** Present the concrete migration diff for approval, then apply authorized changes: router, CLAUDE import, gates in `.geppetto/bin/`, empty authorizations, meta-skills and missing test infrastructure. Follow [installation](references/installation.md) for the shipped `assets/templates/hooks/` and `assets/templates/ci/pr-gate.yml`, trusted first-PR bootstrap, default internal learning nudge and generated-file ownership. Propose host ignore entries for `.agents/skills/**` and `.geppetto/**` for owner consent, preserving vendored bytes. Read `$geppetto-behaviour-tests` for tiers and `$geppetto-memory` for scoped memory configuration. Complete when migration losslessness and `audit.mjs --verify` pass, the host's affected-file check passes, gate fixtures and router budget pass, and fresh Claude Code/Codex loading is demonstrated; report each remaining `NOT VERIFIED` gap by name.
6. **Resolve uncovered recommendations.** Read [semantic hooks](references/semantic-hooks.md) and reuse verified equivalents and recorded answers. Memory classification operates when the OpenRouter key, selected settings and standing user/project grant exist; follow [credential detection and private entry](references/classifier-setup.md). Record and show measurement without making it an activation gate. Signal learning uses authenticated subscription defaults with no rate or spending cap unless the owner configures one. Register installed extra packs and decided pillars. Complete when accepted additions have prerequisite evidence and consent, explicit refusals are preserved, and each blocked capability has one actionable audit item.
7. **Reconcile and report.** For updates or removal, read the install manifest, compare hashes and reconcile local edits before changing files. Remove only owned, unchanged files or explicitly approved reconciliations. After installation or update, deliver the [🪵 installation checklist](references/choices.md#approval-and-installation-messages), including a reason for every disabled or pending feature. Complete when post-install verification passes and the checklist is delivered, or removal leaves a checked inventory of preserved local work and removed owned files.

Read [companion resolution](references/integrations.md) when a bundled or host skill requires a skill absent from the project. Read [process execution](references/processes.md) before launching tools. Report installation evidence separately from release support: Claude Code and Codex trials are required; Pi/OpenCode need their own trial before being called supported.
