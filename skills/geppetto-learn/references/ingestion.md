# Event-driven signal learning

`signal.mjs` owns the inexpensive append and redaction. It never calls a model, starts a child, waits for assessment or assumes that an unknown budget is zero. Add `--episode <observed-episode-id> --source <project-evidence-reference>` together when provenance is known. Old records remain valid evidence, but missing provenance cannot support an independent-episode claim. IDs identify submissions, not independence. File-tool producers append the same fields to the project log.

## Flow and authority

1. A native `PostToolUse` event consumes a successful append. `Stop` and `SessionStart` also recover changed evidence. Claude Code and Codex use their documented asynchronous command hooks. Hermes uses `pre_llm_call` and `transform_tool_result` in the plugin adapter. The recorder remains independent of host/model latency. A standalone CLI append with no active host stays pending until a supported host event or an explicitly requested learning pass.
2. `learn-dispatch.mjs` reads only the selected project's `signals.jsonl`, learning state and configuration. Source references are opaque evidence links, not paths to open. It sends only allowlisted signal fields to the selected host. It does not read conversations, transcripts or memory. A changed evidence snapshot gets a new semantic assessment when authority, budget and runtime permit it. An in-flight assessment coalesces later appends until another host event can assess the updated snapshot; no concurrent assessor is started for each complaint. No investigation is launched for an isolated or ambiguous judgment.
3. The host assesses the same operational cause using identified independent episodes and gives a motivated, source-linked judgment. Recurring requires cause, alternative explanation, rationale and exact signal/episode/source links. Repeated submissions cannot establish independent episodes. The plural-episode check is necessary, not a sufficient threshold. There is no frequency cutoff, lexical classifier or similarity score. Existing causes require an explicit same/different comparison; uncertainty remains pending.
4. Before each assessment or investigation, the existing `authz.mjs` owner reserves `signal-assessment` or `signal-investigation` against personal and project grants, provider and maximum cost. Trusted current-task consent may be passed by an embedding caller, never inferred from a signal, a project setting or model output. Enabling configuration grants no authority. Host-enforced scope, actual provider routing and budget controls must be verified separately; configuration labels are not proof of sandbox isolation. Unknown maximums prevent launch.
5. A project-local exclusive claim serializes assessment, cluster decisions and dispatch. Each attempt is saved as `dispatching` before the host call. Only native acknowledgement supplies `runId` and changes it to `running`. PID creation, hook completion, a reminder, or a pending record is not acknowledgement. An unresolved cause owns its investigation. A new assessment may attach new evidence without creating another child for that cause.
6. Investigation uses `$geppetto-learn`, existing owners, `$geppetto-reuse-it`, `$geppetto-measure-it` and `$geppetto-verify`. Its structured outcome is `keep`, `reject` or `pending`, with owner, rationale, evidence references and limitations. Only inspectable outcomes advance covered evidence. An exact episode replay receives assessment but does not reopen a closed cause. Material new evidence needs an explicit reconsideration before another investigation.
7. Authoritative actual USD settles the existing reservation. Token/API-call counts and the child's own price guesses are not authoritative prices. Unknown actuals retain their maximum and block later automatic learning spend. A known cost above the authorized maximum settles truthfully but also pauses automatic spending until the owner resolves the overrun; it is never clamped to the reservation. A completed investigation and a retained improvement remain distinct from accounting completion.

All autonomous activation, continuing budgets, publication, transcript access, memory access and rollout require their own authority. The shipped `hooks.signalLearning` default is disabled, with unknown provider/boundary/maximums. Local synthetic development is not a keep decision for production activation. The existing deterministic `learnNudge` remains a reminder with its own thresholds; those thresholds never decide recurrence. Periodic learning remains optional fallback, not an ingestion dependency.

## Native adapters and limits

- **Codex** uses `codex exec --json`, a read-only assessment sandbox, the explicitly configured investigation sandbox and optional model selection. It acknowledges `thread.started.thread_id`, reads the last completed `agent_message`, and requires a terminal turn and clean process exit. It never uses permission-bypass flags. The protocol exposes token usage, not authoritative USD. Without external verified budget enforcement it stays pending before launch; without authoritative accounting after a run it retains the reservation. An embedding caller can provide trusted accounting, or the operator can reconcile cost before continuation. A fresh CLI session, not an undocumented native subagent API, performs this scoped investigation.
- **Claude Code** uses print mode with verbose `stream-json`, `system/init.session_id` acknowledgement and a matching `result`. `--max-budget-usd` is explicit. Assessments disable built-in tools, and `mcp__*` is denied separately. Investigation tools default to none; an operator can narrow them to the supported file tools. `dontAsk` preserves denials instead of bypassing permissions. Reported native `total_cost_usd` rounds upward to micro-dollars for the existing ledger. Provider routing and the host's actual privacy/budget boundary still require verification. A fresh noninteractive CLI session performs the investigation.
- **Hermes** uses only `ctx.subagent_lifecycle` with documented `SubagentLaunchRequest`, a leaf role, the exact parent session and correlation ID. Native handles acknowledge actual children; opaque capabilities stay in plugin memory, not project logs. Later host callbacks poll `result`; cancellation acknowledges only `CANCEL_REQUESTED` until a terminal result arrives. Unsupported lifecycle APIs, inactive parents and lost handles remain pending. Hermes currently rejects per-launch working-directory/timeout overrides and provides API-call counts rather than USD. The parent must already enforce the permitted directory/tools and external budget boundary. No internal `AIAgent`, gateway or delegate implementation is imported. A separate trusted accounting adapter is needed for fully automatic cost settlement.

Subprocesses use hidden Windows flags and inherit the caller's scratch temporary directory. Child CLI runs set `GEPPETTO_LEARNING_CHILD=1`, suppressing memory/classifier and nudge hooks while preserving authorization protection. Native Hermes tracks its learning children through `subagent_start` and also suppresses their memory and nudge callbacks. Native hosts can load other ambient context or integrations; a verified isolated parent/CLI configuration is still required before activation. No watcher, scheduler, detached helper, provider client or new credential path is added.

Async native hooks are host-owned and can be terminated when their session ends. A detached parentless recorder cannot promise immediate assessment. Hermes children and handles do not survive host process exit. The local claim is deliberately not a timed lease: after interruption, inspect the actual child and ledger before removing a stale claim. There is no automatic retry, TTL, backoff or invented retry count. CLI cancellation/reconnection after the command-hook process disappears is not implemented; unresolved attempts stay held rather than spawning replacements.

## Configuration and ownership

`common.mjs` owns the disabled default. `hooks.signalLearning` supports `enabled`, `benchmark`, `provider`, `boundary`, `assessmentMaxUsd`, `investigationMaxUsd`, optional exact signal `scope`, and per-runtime `hosts`. Each CLI entry binds its actual `provider`, verified `boundary` and `budgetControl` reference, optional executable/model, and explicit sandbox or file-tool selection. Absent capability, boundary, budget-control evidence or executable means pending. Do not copy synthetic zero-cost fixture values into production. No future model, reasoning level, tier or spending amount is selected by this feature.

The canonical Hermes plugin source is [the hook template](../../geppetto-adopt/assets/templates/hooks/hermes/__init__.py), with `learning.py`, `bridge.mjs`, `plugin.yaml` and `settings.example.json` beside it. The bridge preserves the installed plugin's memory-index and deterministic-nudge behavior. Its private local settings bind project/source/Node paths and separately verified learning provider, boundary and budget controls. The generic skill installer does not install Hermes plugins or touch a live profile. Package a candidate outside the profile, reconcile settings and local edits, review and separately authorize installation; the owner restarts Hermes. Keep a copy of the old plugin for rollback. The issue's development candidate does not include usable live settings.

## Recovery and querying

Run `node .geppetto/bin/learn-host.mjs --status --project <root>` to inspect status, attempts, native IDs, assessments, outcomes and unassessed evidence without launching an agent. New appends cannot silently inherit an old `keep` status when no host is available.

For trusted operator/native reconciliation, the module exports `reconcileLearning(root, request, {authorize})`. Supply the exact `attemptId`, an authoritative `actualUsd` and a source `reference`. A failed or ambiguous run may be retried; a completed run cannot be replayed as a retry. A retry additionally requires `confirmedStopped: true` and `retry: true`. An already acknowledged child must be terminal before reconciliation. This settles the original ledger reservation and retires that attempt; a subsequent authorized event may reserve one new ID. A lost acknowledgement alone is not non-running proof. An overrun stays visible; clearing its automatic-spend hold additionally requires the trusted owner's `confirmedBudgetResolution: true` and the reconciliation source reference. Do not use model output as reconciliation evidence. Cost reconciliation alone never declares an unknown launch stopped. No hook invokes this operator function automatically.

## Observability

Ignored `.geppetto/learning/state.json`, written with restricted local mode, records the evidence snapshot, judgment and source IDs, cluster cause, claim/attempt ID, host, provider, maximum, reservation decision/reference, native acknowledgement and completion timestamps, terminal result, actual/unknown cost, outcome and recovery decision. `.geppetto/signals.jsonl` remains the append-only evidence owner. `--status` marks unassessed changed evidence pending even when an earlier snapshot had an outcome. Existing nudge telemetry remains in `hook-events.jsonl` and is not dispatch telemetry.

This improves traceable completion and duplicate prevention at the cost of local state, authorization-ledger operations and explicit host assessment/continuation work. Recording has no model cost; assessment is not assumed free. Native terminal results and schema validation do not prove the quality of semantic judgment, episode independence, grant-scope interpretation, a measurement or a claimed improvement. `$geppetto-verify` and the operator still own those judgments. Unbounded history/cluster growth is not a measured production workload; an oversize native request fails pending rather than choosing an unapproved retention or context threshold.

## Verification

`tests/learn-dispatch.test.mjs`, `learn-hosts.test.mjs` and `learn-integration.test.mjs` exercise the recorder, changed evidence, source/provenance validation, isolated/pending decisions, acknowledgement/result matching, unresolved claims, replay dedupe, concurrent processes, permission revocation, unknown cost, failed dispatch and explicit retry. Actual hidden subprocesses implement protocol-faithful Codex/Claude doubles and a fixture owner correction with before/after/verification artifacts. `tests/hermes-learning-fixture.py` loads the canonical plugin with an injected documented lifecycle service and temporary settings/grants; it never imports a live Hermes agent or provider. The Node suite reports a skip if Python is unavailable. Local fixture execution is not a production semantic benchmark, real harness integration, cost-cap verification, independent code review or activation approval.
