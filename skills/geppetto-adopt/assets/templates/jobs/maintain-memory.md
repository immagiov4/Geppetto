# Maintain memory

Use $geppetto-memory to maintain the buckets of the machine memory repository. Keep generalizable lessons and decision rationale: consolidate events into lessons, merge duplicates, drop material held by another owner, reconcile contradictions and repair indexes. From the memory repository root, search with `rg <pattern>`; `git log -p <page>` shows why a fact changed. Check the [provenance](../../../../geppetto-memory/references/layout.md#provenance) of changeable facts: recheck at their owners those whose `verified` or `added` date is missing or oldest, then record `verified` or update or remove the entry. When Git access is available, recover a missing `source` or `added` from `git log -p`, report entries whose origin it cannot show instead of inventing one, and following the [shared checkout](../../../../geppetto-memory/references/shared-checkout.md) rules consolidate and commit native memory changes that remain uncommitted while reporting other writers' stale paths. In a file-tools-only scheduled run without Git access, keep edits local for review and report facts missing provenance and native-memory pages that still need Git inspection or commit. Verify the changes and complete the skill's Deliver step.

Run processes through the process-execution reference. Report the inspected scope, useful changes and verification result.

The resolved context includes project outcome reports. Report evidence recurring after a learning change as did not fix, and changed memory pages never read since it as candidates to revert. Preserve the actual references and observation window; a missing read is evidence of unobserved use, not proof that the page is wrong. Record Evidence: <keys> with each learning change and resolve keys only after a committed change or an explained no-change decision. Retain blocked or staged evidence for review.
