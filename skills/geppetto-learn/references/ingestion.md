# Background learning

`learn-runner.mjs` consumes new transcript evidence and records from the project's ignored `.geppetto/signals.jsonl`, takes `~/.geppetto/learn.lock` and creates a Git worktree branch under `~/.geppetto/worktrees/`. The shared Stop handler launches it directly in the background after the configured learning thresholds, including when PostToolUse already supplied the internal reminder. Pending explicit signals also qualify a short turn. It freezes current permitted project files, including staged and unstaged changes, new non-ignored files and deletions, through a separate Git index. The user's index and working files stay intact. Private paths, credentials and harness configuration retain the file tool's exclusions. The lock covers capture, the CLI call and finalization across every project on the machine. Successful runs save the last consumed signal in `.geppetto/learning.json`; failure retains the signals for another run.

For Claude and Codex transcripts, the runner reads complete JSONL records from the session's last processed byte offset under `.geppetto/hook-state/<session-hash>/transcript.json`. User and assistant text is retained; tool calls carry their name and at most 300 argument characters, and only failing tool outputs are retained, at most 500 characters each. Slices larger than 40 KiB retain the head, tail and every user message in conversation order. When user messages alone exceed that budget, the run reports an error and retains its cursor for inspection. A cheap pre-check looks for correction words, tool errors or a review block; an empty result advances the cursor without a model call. Busy, failed and blocked runs leave eligible evidence pending. Pre-check words are an admission heuristic and can miss implicit corrections.

The state records `sourceHead`, the captured `baseline`, and `excludedChanges` for changes outside the permitted file scope, including submodule contents that are not copied into the learning worktree. A snapshot commit contains the input project state; review the learner's improvement with `git diff <baseline> <branch>`. The final learning commit contains only changes made after that baseline. Integrate that improvement against the current project state, preserving work performed since capture.

Both CLIs return a structured assessment with `decision`, `reason` and `owner`. `applied` requires a retained file change; `no_change` requires an evaluated signal set with no file changes and an explanation of existing coverage or why no owner is needed. A blocked assessment retains the previous consumed-signal cursor and records its reason and worktree without committing partial work. Missing, malformed or contradictory assessments fail without consuming signals. Pending evidence is retried on a later invocation, so an unresolved access problem can repeat work until its owner or scope is corrected. A successful process exit alone never establishes completion. Inspect `assessment` in `.geppetto/learning.json` and learning hook events; the isolated host response and schema are retained under `~/.geppetto/learning-<run-id>.json` and its `.schema.json` companion.

The runner starts `codex exec` or `claude -p` with a fixed learning prompt. Set `hooks.signalLearning.model` when a task requires a particular model; Codex also accepts `hooks.signalLearning.reasoningEffort`. These selections are passed explicitly because the isolated child does not load the caller's configuration. Without a selection, the child uses its CLI default. The prompt names the installed `geppetto-learn` procedure; Read can access that package's bundled procedures and references, while Write and Edit remain confined to project files. API-key routing is removed from the subscription child's environment. Only bounded Read, Write, Edit, Glob and Grep tools are exposed through `learner-tools.mjs`: **no shell, delegation or push**. The adapter excludes private buckets, credentials and harness configuration. The parent stages validated paths and creates the local commit. `hooks.signalLearning.writeApproval: true` leaves changes staged for review; the default is false.

`hooks.signalLearning.enabled: false` disables background learning. Inspect `.geppetto/hook-events.jsonl` for the outcome and worktree location. A failed run leaves its worktree for inspection. The installation audit reports an exited lock owner or an unverifiable owner as a readiness blocker. If a process was killed, verify its recorded PID has exited before removing a stale machine lock.

## Observability

Learning events retain originating session/turn identifiers, decisions, failures and worktree locations. Per-session cursors identify consumed transcript bytes; source text and transcript slices stay out of hook-event records. The admission pre-check and reducer use no model calls. Background execution uses the configured subscription model and machine lock; blocked and invalid structured assessments preserve pending evidence. Synthetic behavior tests cover reduction, cursor reuse, oversize user text, retries and provider-free admission.
