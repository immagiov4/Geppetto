# Event-driven signal learning

`signal.mjs` owns the inexpensive append and redaction. It never calls a model, starts a child, waits for assessment or assumes that an unknown budget is zero. Add `--episode <observed-episode-id> --source <project-evidence-reference>` together when provenance is known. Old records remain valid evidence, but missing provenance cannot support an independent-episode claim. IDs identify submissions, not independence. File-tool producers append the same fields to the project log.

## Flow and authority

1. A native `PostToolUse` event consumes a successful append. `Stop` and `SessionStart` also recover changed evidence. Claude Code and Codex use their documented asynchronous command hooks. Hermes uses `pre_llm_call` and `transform_tool_result` in the plugin adapter. The recorder remains independent of host/model latency. A standalone CLI append with no active host stays pending until a supported host event or an explicitly requested learning pass.
2. `learn-dispatch.mjs` reads the selected project's signal log, state and policy, forwarding only allowlisted redacted signal fields. Source references are opaque evidence links. Changed evidence receives a semantic assessment when an authorized host is available. An in-flight assessment coalesces appends until the next event; isolated or ambiguous judgments launch no investigation.
3. The host judges whether evidence describes a reusable workflow, a dead end with a verified fix, a user correction or a recurring operational cause. One source-linked episode can support `reusable`; `recurring` requires identified independent episodes. Each actionable judgment supplies cause, alternatives, rationale and exact signal/episode/source links. Existing causes require same/different comparison; uncertainty stays pending. Submission counts and lexical similarity do not establish learning value.
4. Before each native launch, `authz.mjs` records an authorization reservation. Subscription learning uses the accepted project `signal-learning` grant and authenticated Codex/Claude subscription, with zero API charge. Paid API routes need their provider key and personal plus project `signal-assessment`/`signal-investigation` grants. Unlimited paid authority is explicit (`budget_usd=none`); configured USD ceilings still require bounded reservations and host enforcement. Configuration, signal text and model output cannot create consent. Adoption asks once, defaults yes and records accepted subscription consent with `learning-setup.mjs --accept`. Publication, transcripts and private memory remain separately authorized.
5. A project-local exclusive claim serializes assessment, cluster decisions and dispatch. Each attempt is saved as `dispatching` before the host call. Only native acknowledgement supplies `runId` and changes it to `running`. PID creation, hook completion, a reminder, or a pending record is not acknowledgement. An unresolved cause owns its investigation. A new assessment may attach new evidence without creating another child for that cause.
6. Investigation follows `$geppetto-learn`, existing owners, reuse, measurement and verification. Its outcome is `keep`, `reject` or `pending`, with owner, rationale, evidence references and limitations. Subscription investigation uses a fresh `geppetto/learn-<attempt-id>` Git worktree from the current commit. File changes remain isolated from the working branch. After a valid outcome and a fresh grant check, trusted integration stages the changes and commits a `keep` unless `writeApproval` is true; true retains staged changes for review. Rejected/pending changes also stay staged. Exact replay cannot reopen covered evidence; material new evidence needs explicit reconsideration.
7. Paid actual USD settles the reservation when the provider reports it. Unknown charges remain visible; a configured maximum stays reserved and blocks further bounded spending until reconciliation. With an explicit unlimited grant, unknown billing alone imposes no new cap. An ambiguous launch still blocks duplicates. A measured overrun settles truthfully and pauses further work until resolved. Subscription runs record zero API charge after authenticated subscription routing; token counts never imply a price.

`hooks.signalLearning` defaults enabled whenever its CLI/authentication and standing-consent prerequisites are present. There is no default daily-run, concurrency-rate or USD cap: the agent judges need from the signals. Optional `maxRunsPerDay` (rolling 24 hours), `maxConcurrentRuns`, `assessmentMaxUsd` and `investigationMaxUsd` apply only when configured by the owner. The project claim and unresolved native attempts prevent duplicate work regardless of optional limits. The deterministic `learnNudge` remains a separate reminder; periodic learning is an optional fallback.

## Native adapters and limits

- **Codex** uses `codex exec --json`, model `gpt-6.1-sol`, default service tier, read-only assessment and workspace-write investigation. It acknowledges `thread.started.thread_id` and requires a terminal turn plus clean exit. Subscription invocations force ChatGPT login, ignore user configuration and remove API-routing credentials. Shell, delegation, apps, plugins, browser, memory and automatic MCP installation are disabled; the configured MCP map exposes only the bounded project file tools `Read`, `Edit`, `Write`, `Glob`, `Grep` during investigation. Permission bypass is unavailable. Codex token usage is not a paid USD total; paid routes keep authoritative accounting separate.
- **Claude Code** is the subscription alternative when Codex is absent. Print mode uses verbose `stream-json`, native `system/init.session_id` acknowledgement and a matching terminal `result`. Subscription authentication must report `claude.ai` or `oauth_token`; API-routing environment variables are removed. Strict MCP configuration exposes the same project file tools, built-in tools are disabled, and `dontAsk` preserves denials. Paid configurations receive `--max-budget-usd` only for a configured maximum; native cost rounds upward to ledger micro-dollar precision.
- **Hermes** uses only `ctx.subagent_lifecycle` with documented `SubagentLaunchRequest`, a leaf role, the exact parent session and correlation ID. Native handles acknowledge actual children; opaque capabilities stay in plugin memory, not project logs. Later host callbacks poll `result`; cancellation acknowledges only `CANCEL_REQUESTED` until a terminal result arrives. Unsupported lifecycle APIs, inactive parents and lost handles remain pending. Hermes currently rejects per-launch working-directory/timeout overrides and provides API-call counts rather than USD. The parent must already enforce the permitted directory/tools and external budget boundary. No internal `AIAgent`, gateway or delegate implementation is imported. A separate trusted accounting adapter is needed for fully automatic cost settlement.

Subprocesses use hidden Windows flags. CLI children set `GEPPETTO_LEARNING_CHILD=1`, suppressing memory/classifier and nudge hooks while retaining grant protection. Native Hermes tracks its learning children through lifecycle callbacks. `learning-files.mjs` confines file tools to the selected project/worktree, rejects symlinks, credentials, private directories and runtime/grant configuration, and redacts reads. The trusted Git finalizer validates changed paths before staging, disables Git hooks and never pushes. It starts from committed project files; uncommitted parent edits are outside that learning snapshot. Synthetic protocols establish these arguments and file boundaries; actual host sandbox enforcement and semantic quality still need production evidence.

Async native hooks are host-owned and can be terminated when their session ends. A detached parentless recorder cannot promise immediate assessment. Hermes children and handles do not survive host process exit. The local claim is deliberately not a timed lease: after interruption, inspect the actual child and ledger before removing a stale claim. There is no automatic retry, TTL, backoff or invented retry count. CLI cancellation/reconnection after the command-hook process disappears is not implemented; unresolved attempts stay held rather than spawning replacements.

## Configuration and ownership

`common.mjs` owns enabled subscription defaults; `learning-config.mjs` resolves policy and probes CLI authentication without a model call. `learning-setup.mjs` records the accepted adoption answer once; repeated adoption preserves refusals and existing grants. `audit.mjs` reports actual readiness and the first actionable missing prerequisite. `hooks.signalLearning` supports `enabled`, `benchmark`, `host`, `billing`, `provider`, `boundary`, `writeApproval`, optional exact signal `scope`, optional owner-selected caps and per-runtime `hosts`. CLI entries accept executable/prefix overrides, model, service tier, sandbox and file tools. Paid routes retain verified provider/boundary and, when capped, `budgetControl`. A benchmark records measurement without gating readiness.

The canonical Hermes plugin source is [the hook template](../../geppetto-adopt/assets/templates/hooks/hermes/__init__.py), with `learning.py`, `bridge.mjs`, `plugin.yaml` and `settings.example.json` beside it. The bridge preserves the installed plugin's memory-index and deterministic-nudge behavior. Its private local settings bind project/source/Node paths and separately verified learning provider, boundary and budget controls. The generic skill installer does not install Hermes plugins or touch a live profile. Package a candidate outside the profile, reconcile settings and local edits, review and separately authorize installation; the owner restarts Hermes. Keep a copy of the old plugin for rollback. The issue's development candidate does not include usable live settings.

## Recovery and querying

Run `node .geppetto/bin/learn-host.mjs --status --project <root>` to inspect status, attempts, native IDs, assessments, outcomes and unassessed evidence without launching an agent. New appends cannot silently inherit an old `keep` status when no host is available.

For trusted operator/native reconciliation, the module exports `reconcileLearning(root, request, {authorize})`. Supply the exact `attemptId`, an authoritative `actualUsd` and a source `reference`. A failed or ambiguous run may be retried; a completed run cannot be replayed as a retry. A retry additionally requires `confirmedStopped: true` and `retry: true`. An already acknowledged child must be terminal before reconciliation. This settles the original ledger reservation and retires that attempt; a subsequent authorized event may reserve one new ID. A lost acknowledgement alone is not non-running proof. An overrun stays visible; clearing its automatic-spend hold additionally requires the trusted owner's `confirmedBudgetResolution: true` and the reconciliation source reference. Do not use model output as reconciliation evidence. Cost reconciliation alone never declares an unknown launch stopped. No hook invokes this operator function automatically.

## Observability

Ignored `.geppetto/learning/state.json` records snapshots, judgments, source IDs, causes, attempts, host/billing/provider, optional maximum, consent reference, native acknowledgement and terminal timestamps, actual/unknown cost, outcomes and reconciliation. Investigation attempts additionally record the isolated branch/worktree and staged/committed result with file paths and commit ID. `.geppetto/signals.jsonl` remains append-only evidence. `--status` marks changed unassessed evidence pending. Nudge telemetry remains in `hook-events.jsonl`. Audit emits one readiness/action line each for signal learning and memory classification.

This improves traceable completion and duplicate prevention at the cost of local state, authorization-ledger operations and explicit host assessment/continuation work. Recording has no model cost; assessment is not assumed free. Native terminal results and schema validation do not prove the quality of semantic judgment, episode independence, grant-scope interpretation, a measurement or a claimed improvement. `$geppetto-verify` and the operator still own those judgments. Unbounded history/cluster growth is not a measured production workload; an oversize native request fails pending rather than choosing an unapproved retention or context threshold.
