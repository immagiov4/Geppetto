# Adopt

Restructure what already works with the maintainer. Read [installation and script contracts](references/installation.md) before operating on files; read `$writing-for-agents` before changing instructions. Use [templates](assets/templates/AGENTS.md) as material to adapt, not as permission to replace existing rules.

1. **Probe.** Run `node <adopt>/scripts/audit.mjs --project <project> --json`. Inspect instruction/skill discovery, hooks, scheduling, plugins, memory, Node, Git, `gh` and review prerequisites for each target harness. Mark each capability present, absent or unverified. Complete when the capability table distinguishes observations from assumptions.
2. **Inventory.** Use the instruction-migration helper described in [installation](references/installation.md) to inventory every AGENTS/CLAUDE section. Classify routing, obligations, guidance to relocate and obsolete material; preserve content at its owner or record an approved drop. Inventory local skills, extra packs, docs, tests, CI, observability and host formatter/linter configuration. Complete when every section and pillar has a disposition and each vendored-path conflict is visible.
3. **Recommend.** Report pillars by harness, required or recommended status, evidence and reason. An equivalent existing implementation satisfies a pillar; Geppetto's principle skills still ship complete. Complete when each row has a state and rationale, including missing capabilities and their existing-tool alternatives.
4. **Ask once.** Read [project choices](references/choices.md). Present one grouped round with defaults only after [verifying existing equivalents](references/choices.md#verify-before-asking), reusing recorded answers and verified hooks/jobs; include which memory buckets to link in `memory.buckets` for full-index injection, and explicitly offer uncovered periodic learning, skill curation and memory maintenance as separate choices. Save answers in `.geppetto/config.json`. Keep `code-review` and `receive-work-feedback` unless the maintainer explicitly selects their own skill or external reviewer. Complete when configuration records every relevant choice and unresolved choice is named.
5. **Install required pillars.** Present the concrete migration diff for approval, then apply authorized changes: router, CLAUDE import, gates in `.geppetto/bin/`, empty authorizations, meta-skills and missing test infrastructure. Follow [installation](references/installation.md) for the shipped `assets/templates/hooks/` and `assets/templates/ci/pr-gate.yml`, trusted first-PR bootstrap, default end-of-turn learning nudge and generated-file ownership. Propose host ignore entries for `.agents/skills/**` and `.geppetto/**` for owner consent, preserving vendored bytes. Read `$geppetto-behaviour-tests` for tiers and `$geppetto-memory` for scoped memory configuration. Complete when migration losslessness and `audit.mjs --verify` pass, the host's affected-file check passes, gate fixtures and router budget pass, and fresh Claude Code/Codex loading is demonstrated; report each remaining `NOT VERIFIED` gap by name.
6. **Resolve uncovered recommendations.** Read [semantic hooks](references/semantic-hooks.md) to explain the experimental, disabled-by-default skill selector, memory-page classifier and requirements screen; recommend an optional selector benchmark alongside the project router. Reuse verified equivalents and answers from step 4 instead of offering them again. For accepted setup, follow [credential detection and private entry](references/classifier-setup.md) before the separately authorized benchmark and keep decision. Register installed extra packs and record decided pillars through [project choices](references/choices.md). Complete when accepted additions have evidence and consent, and unanswered choices are reported as pending and stay disabled.
7. **Reconcile.** For updates or removal, read the install manifest, compare hashes and reconcile local edits before changing files. Remove only owned, unchanged files or explicitly approved reconciliations. Complete when post-install verification passes, or removal leaves a checked inventory of preserved local work and removed owned files.

Read [companion resolution](references/integrations.md) when a bundled or host skill requires a skill absent from the project. Read [process execution](references/processes.md) before launching tools. Report installation evidence separately from release support: Claude Code and Codex trials are required; Pi/OpenCode need their own trial before being called supported.
