# Hook operation

The plugin supplies global hooks. The installer reuses them with `--plugin-hooks`, or merges one shared hook set into user settings. `~/.geppetto/machine.json` records the source. SessionStart injects memory listings and the turn-record command and schema; UserPromptSubmit captures the turn boundary without adding context; PreToolUse gates native file edits and pending shell effects and checks PR text; PostToolUse observes Git changes, re-arms feedback after configured review results and supplies one internal learning reminder per user prompt after a current positive feedback or frustration decision, or a qualifying long turn; Stop checks frustration outcomes and independent review; the next tool result offers eligible evidence to the working session.

## Activation

After installing, changing or curating a hook, synchronize every authorized copy and complete activation of the final definition in each affected harness and project. Finish package refreshes, including a Git-backed plugin cache's revision update, before approving its hashes; a later refresh can invalidate the approval even when hook commands stay the same. An authorized hook change, including a metric-justified improvement already authorized by the user, includes its activation; do not ask for consent again for that completion. A change to permissions or effects beyond the approved change is a separate decision.

- **Codex:** update the plugin through Codex first, then run the installer, which approves Geppetto's final installed scope and verifies trust through `hooks/list`. User hooks are selected by owned command keys within the shared file; plugin hooks require a unique identity and executable content matching the authorized package. A later plugin update changes its content hash and requires another installer run. A blocked approval leaves installed files intact and prints the installer command to retry, preserving package and command ownership checks. Use `node <adopt>/scripts/codex-hook-trust.mjs --project <project>` to inspect missing or ambiguous scope, resolve it, then rerun that installer command. Inventory trust establishes approval. Verify execution separately through a native `hook/completed` notification or a new `hook-events.jsonl` record matching the target session's `sessionId`. Open a new session to load the final definition until reloading in an already open session has been observed.
- **Claude Code:** settings edits are normally picked up by its file watcher. Confirm the intended hook is enabled and observed in the target session; reload the plugin or start a fresh session if that session has not loaded the final definition. Use the native `/hooks` view and debug output when needed.
- **Hermes:** enable the installed plugin with `hermes plugins enable <name>` in the intended profile, then ensure the serving process has loaded the final version (restart or reload it where required). Verify the hook's effect in that same profile and serving process. A plugin on disk or an enabled flag alone is not proof that its hook is running.

If activation cannot be completed, report the exact blocker and leave the hook's active state unclaimed. Keep changes within the authorized installation and project scope.

## Result attribution

Result records in the repository's shared `hook-events.jsonl` under `<git-common-dir>/geppetto/` (or `.geppetto/` outside Git) include `sessionId` and `turnId` when the triggering harness supplies them. Match these identifiers to the session being investigated before attributing a result: probes and other sessions can write to the same project log. Historical records and events from harnesses without identifiers remain unattributed. The log records selected Geppetto outcomes; native `hook/started` and `hook/completed` events identify failures before a script starts, including Codex plugin-content approval failures.

## Learning

`learn-nudge.mjs` records tool activity and adds one internal reminder per qualifying user-message episode, including steering within a native turn, using the configured tool-count or elapsed-time threshold. The current agent applies `$geppetto-learn` before replying. The handler uses zero model calls; reflection uses the ordinary session. Events record firings and duplicate suppression state stays under ignored `.geppetto/hook-state/`.

The [learning record](../../../../geppetto-learn/references/ingestion.md) closes frustration in the current user turn. Use `--record-turn` with `{"learning":{"outcome":"lesson","path":"AGENTS.md","reason":"<prevention>"}}` after changing the owner. Other outcomes are `covered` with an existing rule path, `one-off` with a reason, or `blocked` with owner path, reason and key. Include `key` to close a signal. Stop blocks on a missing outcome or unchanged lesson owner. Codex retries require an outcome or a recorded Stop override. Claude asks once. Check errors are recorded and let the turn end. [Maintenance jobs](../../../../geppetto-learn/references/jobs.md) curate existing procedures.

PostToolUse also recognizes Write/Edit/MultiEdit and apply_patch paths in Claude's native memory, configured `autoMemoryDirectory` and Codex's `<CODEX_HOME>/memories/`. With bucket memory configured it reminds once per turn to save durable lessons through `$geppetto-memory`; a native directory inside a bucket instead prompts index upkeep. This uses the existing dispatch, an exclusive turn marker and a zero-model-call `nativeMemory` event in the same hook log. Native-only and no-memory choices keep bucket hooks silent. The end-of-turn nudge includes lessons and decision rationale without another owner.

Hermes uses its [plugin template](hermes/plugin.yaml) for read-only memory listings and learning reminders. Copy `settings.example.json` to the profile's `settings.json` and resolve its paths.

## Review gate

`hooks.reviewGate` is enabled by default. Stop blocks when source changed this turn by at least `threshold` added/deleted lines (default 30), the current diff has no matching independent review, and edits since the latest review also reach that threshold. `docGlobs` and `testGlobs` configure exclusions; defaults exclude Markdown, reStructuredText, docs, tests, fixtures and common test filenames. Prompt or first-tool events capture the turn's initial source state, so pre-existing edits alone do not trigger a block. On Codex the block stays active until a matching review or recorded Stop override. On Claude the second attempt can close, and an unavailable reviewer can be reported with `Independent review blocked: <concrete reason>`.

Complete `$geppetto-verify` or its configured `code-review` engine to record the reviewed diff. The review record holds a SHA-256, resolved comparison base, timestamp and outcome in shared `reviews.jsonl`, with originating worktree and revision; comparison state under `.geppetto/hook-state/` holds only line hashes. Source and diffs stay out of these files. Tracked and non-ignored untracked text source count; binary files, symlinks and submodule contents are outside this gate's line measure. Review eligibility remains specific to the originating checkout. The gate verifies review identity, while the review procedure owns independence and findings.

Git diff output streams into the fingerprint, including patches larger than 1 MiB. Collected Git text output, including repository inventories, has no fixed subprocess buffer limit; callers can set an explicit `maxBuffer`. These reads retain their output in memory. Any PreToolUse or PostToolUse error allows the tool and emits one redacted diagnostic line on stderr. Any Stop error lets the turn close and records one redacted error per session/turn in `hook-events.jsonl`. Manual recording commands retain their error exit codes. If the diagnostic itself cannot be persisted, stderr retains its cause.

## Turn record

Before the first file-modifying tool call after each user message, record the configured decisions with `node <adopt>/scripts/hook.mjs --record-turn '<json>' --session <session-id>` from the project root. This includes a message received while the same native turn is still running. SessionStart supplies the resolved command, questions, skills and minimal schema once per session. Edit-free turns need no record. An explicit `--turn <turn-id>` checks the identity; `--record-turn -` reads JSON from stdin. If the current decision is missing, PreToolUse denies the edit and supplies the command and schema. Codex keeps denying edits until a decision or recorded edit override. Claude asks once per epoch. An explicit override is `{"override":{"gate":"edit","reason":"<specific reason>"}}` or the same record with `gate: "stop"`. It applies only to the current decision epoch. A pending foundation still needs its recorded decision.

Native transcripts are append-only. When one is available, the handler reads appended complete records to identify new text-bearing user messages. It retains byte position and message identity, then renews the existing decision record. An observed truncation or replaced file resets the cursor. When native turns alternate within a session, each retains its own saved state and transcript cursor. Explicit recording commands and signals resolve that turn’s state. Session-state reads and changes share a local lock; an abandoned lock reports its owner for recovery. Tool-result envelopes and review results keep their own handling. A new user assessment governs signal provenance; review-only assessments preserve that provenance. `turnGate/user-message` and `turnGate/resumed` record bytes read with zero model calls. Learning qualification is counted within the same message episode, and lesson baselines are refreshed at user-message boundaries. An unavailable or malformed transcript records `turnGate/transcript-unavailable` and leaves native turn handling active.

Write/Edit/MultiEdit, namespaced apply_patch and MCP file-writing tools receive the preventive check. Shell commands run freely. At each PostToolUse, Git porcelain status and changed-path size, modification time and change time are compared with the turn's initial fingerprint, then with the last observed fingerprint. A change without a current decision requests the record at the next tool call, even a read; the first shell edit can precede the request. This observes tracked, staged and non-ignored untracked changes, including changes to already-dirty files. Git-ignored files and Geppetto's runtime ignore file are outside this observation. Run `audit.mjs --metrics` for join coverage, decision dispositions, unreconciled Stop epochs and retry counts per machine and harness. Historical records without a stable identity remain unclassified. The edited-turn metric counts admitted native edit attempts and observed Git changes; a failed native tool can still leave no changed bytes.

`.geppetto/config.json` accepts `turnChecks` as an array of `{id, question, skill}`. To configure review-result matching, use `{ "checks": [...], "rearmOn": [...] }`; omitted members inherit the bundled defaults in `scripts/turn-checks.json`. Installation and audit validate the definitions. An empty checks array disables decision requests. SessionStart and validation derive from the same list. Built-in IDs retain the schema below; other IDs use `{ "applies": false }` and require a meaningful one-line `reason` when true.

```json
{"requirements":{"changes":false},"feedback":{"applies":false},"frustration":{"applies":false}}
```

Use `requirements.changes: true` for substantial changes to software product behavior or agreed product requirements; tiny localized edits, standalone documentary research, prose work and unrelated tasks use false; run `$requirements-blast-radius` against the original request and agreed changes, and put the changed point in `what`. Classify foundational work using `$geppetto-spec`. Set `requirements.foundation` to `pending` while the decision is open. The edit gate rejects repeated attempts with that state. Use a populated `foundations.<key>` or a Markdown path under an `adr/` directory for an existing decision. To create an ADR after the user approves the decision, pass `{ "adr": "docs/adr/001-choice.md", "approvedDecision": "<full record>" }` as the field value. The recorder creates only a new file and stores its path in the turn. For substantial changes without a foundation, set the field to false. Ordinary local edits may omit it. For feedback from the user, a reviewer, CI or a delegated agent, run `$receive-work-feedback` and record `feedback.applies: true`, `on` (what the user judged) and `action` (what you did). For frustration caused by your work, use `$geppetto-learn` and record `frustration.applies: true`, `cause` and `prevention` (the owning improvement or signal). Each positive reason is a meaningful single line; placeholders such as `n/a`, `none`, `-`, `ok` and `no` are rejected. Keep reasons concise and free of secrets. For a pure continuation with no user message content to judge, use `{"continuation":true}`. The gate checks the record's structure; the agent owns the judgments and actions.

`rearmOn` rules match `tool` against the tool name without its namespace. A `gh` rule names the subcommand, with optional `path` regex for its first positional argument and `flags` for required options; for example, `{ "tool": "^Bash$", "gh": "pr view", "flags": ["--comments"] }`. Parsing separates positional arguments from options and their values, including repository, header and method options. A `script` regex matches the Python script path on a real run. A `command` regex supports custom command matching; a tool-only rule matches any result from that tool. Help invocations preserve the decision. Defaults cover gh api pull comments/reviews, gh pr view --comments, gh pr checks, the bundled Python code-review script, delegated-result tools and gh run view --log-failed. Unrelated calls preserve the decision; tool-use IDs suppress duplicate result delivery. The next edit requests feedback again, preserving other decisions. A feedback-only record is accepted after a prior decision; continuation cannot bypass renewal. Output text is not classified.

The command stages validated decisions under ignored `.geppetto/hook-state/`; concurrent sessions remain separate. Incompatible active state starts a fresh current turn. Closing Stop appends one line to shared `turns.jsonl`, with gate-computed review metadata, identities, timestamps and transcript path paired with its byte boundary.
Outcome diagnostics use records from that transcript; records without a source path remain in the journal. Each decision in `decisions` retains its value, `requestedAt` and `decidedAt`; their nonnegative waits sum to `addedSeconds`. A proactive decision before any edit request has zero wait. Re-recording the same decision cycle replaces its observation. Optional `userCorrection: true|false` explicitly classifies whether this user message corrects the immediately preceding work; leave it absent when unknown. A pure continuation remains eligible for that declaration.

## Observability

`hook-events.jsonl` records reviewGate outcomes, changed-line counts and current diff hash, turnGate block/rearmed/recorded outcomes, startup context bytes, completion errors and learning events. `turns.jsonl` retains the agent's decisions and wait durations for calibration. `audit` reports median added seconds per recorded admitted edited turn, corrections among classified immediate next messages in the same session, and the unknown count. Edit-free messages without a voluntary classification and legacy records remain unclassified; this is an observed sample, not an inferred correction rate. Turns that close without a record are outside the timing sample. The gate uses zero model calls. Its benefit is a decision before editing; startup context, local Git reads and decision recording add interaction cost. Synthetic tests cover config-driven decisions, placeholders, re-arm matching, continuations, isolation, concurrent delivery, error recovery, measurement and review identity. Real Claude and Codex sessions verify edited and edit-free turns separately. Outcome recording and lesson baseline rules belong to the linked learning lifecycle.

### Duration metrics

Run `node <adopt>/scripts/audit.mjs --project <dir> --metrics` to rank observed keys by total duration, compare the latest seven days against the previous seven, and inspect turn decision waits and merged PR cycle times. Add `--key <key>`, `--since <ISO date>`, or `--json` to filter or export the report. The PR sample covers up to 100 recent merges available to the signed-in `gh` client.

Durations come from matching PreToolUse and PostToolUse IDs in the existing activity log. The shared `metrics.jsonl` journal retains normalized command names, elapsed time, known outcomes and repository attribution. Test, check, lint, build and typecheck commands qualify regardless of duration; `metrics.suites` can replace the default classification with regular expressions matched against the normalized key. Git and gh calls also qualify. Other commands qualify from five seconds. Background calls and calls without a matching end event are outside coverage. A suite's scoped count identifies calls with additional positional arguments or test filters.

Delegate wall time merges overlapping spans on each capturing host. Summed resource time adds the spans, including wait calls, and measures tool time rather than worker CPU use. Missing sources appear in the report. Capture failures produce a `metrics` entry in `hook-events.jsonl`, or a diagnostic on stderr when the event journal is unavailable. Capture uses no model calls.

## Timing reminders

A completed timed operation can emit one PostToolUse reminder per key and turn. An explicit expectation takes precedence over a maintainer-approved `metrics.thresholds[key].warnMs`. With five prior observations the slow run must exceed both baseline multipliers and last at least ten seconds. Cold-start floors are one minute for commands and suites and ten minutes for delegates. Each comparison uses preceding observations from the journal.

Use `signal.mjs --metric '<json>' --session <session-id> --turn <turn-id>` with `{"kind":"expectation","key":"git status","expectedMs":500}` before an operation. After a reminder, record `{"kind":"diagnosis","key":"git status","verdict":"expected","reason":"<specific reason>"}`. Use `investigate` to record an efficiency signal. Use `threshold` with `warnMs` to record a proposal and ask the maintainer before editing configuration.

Successful pull request creation and merges produce an elapsed time, recorded review rounds and timing reminder count. `audit.mjs --metrics` reports how many reminders have a diagnosis.
