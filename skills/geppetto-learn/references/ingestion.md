# Background learning

`signal.mjs --list` returns only open key IDs. Recording requires a short key, session and one category from project `categories`; `other` requires concrete evidence. Ordered category objects carry `id`, a one-line definition and `score` (the observation method). Assignment uses the configured order, with one primary category per episode and secondary effects in `attributes`. The shipped order is security, verification, workflow, efficiency, communication and behavior. Legacy records retain their metric fields without a guessed mapping. A key counts once per distinct session. User provenance comes from the first decision of the active turn or its completed feedback/frustration record; an unflagged observation is agent-sourced. An explicit user-source claim requires those flags. Use --source agent for an agent-discovered observation even during a flagged user turn.

The ignored `.geppetto/signals.jsonl` is an append-only evidence archive. Occurrences carry `key`, `source`, `category`, `session` and open status; resolution events add a reference, reason and changed paths. Merges retain `merged-into:<key>` and combine distinct session identities at the destination. The curator proposes a new class only from at least three evidenced other keys across sessions, retaining definition, score method and rationale in `.geppetto/category-proposals.jsonl` for the maintainer's decision. Config replaces the category list without code changes.

User evidence qualifies immediately. Agent evidence qualifies at `hooks.signalLearning.minSessions` (default 2); more than `hooks.signalLearning.maxOpenKeys` (default 10) also starts learning. The recording command launches the background runner when eligible evidence exists, and Stop/weekly maintenance provide recovery. Busy locks, failed launches and blocked decisions preserve evidence. Transcript context alone does not authorize a learning change: an eligible archived signal is required. Long-turn reminders retain their configured tool/duration thresholds and offer only open keys plus the assignment rule.

`learn-runner.mjs` takes `~/.geppetto/learn.lock` and creates a Git worktree under `~/.geppetto/worktrees/`. It captures current permitted project files, including staged/unstaged changes, new non-ignored files and deletions, through a separate Git index. The user's index and working files stay intact. Private paths, credentials and harness configuration retain the file tool's exclusions. The lock covers capture, the CLI call and finalization across projects. Archive status controls consumption; lastId identifies the last assessed occurrence. Legacy records remain consultable for curation and acquire session/category provenance only through an explicit new observation. Failed and blocked runs retain their evidence for another invocation.

For Claude and Codex transcripts, the runner selects complete JSONL records after the session's last processed byte offset under `.geppetto/hook-state/<session-hash>/transcript.json`. It rechecks earlier records for private provenance, resolving path-like arguments against recorded tool working directories (`workdir` or `cwd`) and the session directory, decoding file URIs and comparing real paths with the configured memory repository's `buckets/private/`. Removed files fall back to lexical paths; Git revision paths such as `git show HEAD:buckets/private/facts.md` are also recognized. A private path skips the entire learning invocation, including pending signals, with `skipped: private-memory` and zero model calls. This conservative session exclusion protects later summaries across cursor advances and can also omit a session that only discusses such a path. Signals and turn records naming private paths are excluded. The existing signal redactor removes recognized secrets before tool text is clipped and again before the provider receives the combined evidence. User and assistant text is retained for eligible sessions; tool calls carry their name and at most 300 argument characters, and only failing tool outputs are retained, at most 500 characters each. Slices larger than 40 KiB retain the head, tail and every user message in conversation order. When user messages alone exceed that budget, the run reports an error and retains its cursor for inspection. A transcript pre-check looks for correction words, tool errors or a review block; an empty result advances the transcript cursor without adding context to the eligible signal set. Busy, failed and blocked runs leave eligible evidence pending. Pre-check words are an admission heuristic and can miss implicit corrections.

The state records `sourceHead`, the captured `baseline`, and `excludedChanges` for changes outside the permitted file scope, including submodule contents that are not copied into the learning worktree. A snapshot commit contains the input project state; review the learner's improvement with `git diff <baseline> <branch>`. The final learning commit contains only changes made after that baseline. Integrate that improvement against the current project state, preserving work performed since capture.

The runner also reads the session's [turn records](../../geppetto-adopt/assets/templates/hooks/README.md#turn-record). Transcript byte boundaries associate each subsequent user message with the preceding decision, including across cursor advances. A negative requirements or frustration decision followed by another user message admits a potential calibration candidate: the learner judges whether it is a scope correction after `requirements.changes: false`, or further frustration after `frustration.applies: false`, and retains confirmed lessons at their owner. This mechanical admission deliberately includes ordinary follow-ups; semantic judgment belongs to the learner. It can increase background calls in exchange for covering implicit corrections. Other sessions' records stay outside the supplied evidence.

Both CLIs return a structured assessment with `decision`, `reason` and `owner`. `applied` requires a retained file change; `no_change` requires an evaluated signal set with no file changes and an explanation of existing coverage or why no owner is needed. A blocked assessment retains the previous consumed-signal cursor and records its reason and worktree without committing partial work. Missing, malformed or contradictory assessments fail without consuming signals. Signal occurrences retain their transcript reference so immediate and weekly runs apply the same private-session provenance check before any provider call. Pending evidence is retried on a later invocation, so an unresolved access problem can repeat work until its owner or scope is corrected. A successful process exit alone never establishes completion. Inspect `assessment` in `.geppetto/learning.json` and learning hook events; the isolated host response and schema are retained under `~/.geppetto/learning-<run-id>.json` and its `.schema.json` companion.

The runner starts `codex exec` or `claude -p` with a fixed learning prompt. Set `hooks.signalLearning.model` when a task requires a particular model; Codex also accepts `hooks.signalLearning.reasoningEffort`. These selections are passed explicitly because the isolated child does not load the caller's configuration. Without a selection, the child uses its CLI default. The prompt names the installed `geppetto-learn` procedure and its file-based companion view; Read can access that package's bundled procedures and references, while Write and Edit remain confined to project files. API-key routing is removed from the subscription child's environment. Only bounded Read, Write, Edit, Glob and Grep tools are exposed through `learner-tools.mjs`: **no shell, delegation or push**. The adapter excludes private buckets, credentials and harness configuration. The parent stages validated paths and creates the local commit. `hooks.signalLearning.writeApproval: true` leaves changes staged for review; the default is false.

Before staging any output, the parent joins tracked additions and new file contents into one text and checks it against the local private bucket. It lowercases both sides and collapses whitespace, rejecting text containing an entire private line with at least 20 non-space characters even across added lines or case changes. It also rejects private-bucket paths and blocks output when validation cannot complete. The complete diff read has no implicit subprocess output-buffer limit. Private content stays local to this check. Rejection removes the output worktree and its branch, records `blocked` with a safe reason, and preserves pending signals. It applies even when the learner fails or returns an invalid assessment. Unchanged context and removed lines are outside the added-line check.

`hooks.signalLearning.enabled: false` disables background learning. Inspect `.geppetto/hook-events.jsonl` for the outcome and worktree location. A failed run leaves its worktree for inspection. The installation audit reports an exited lock owner or an unverifiable owner as a readiness blocker. If a process was killed, verify its recorded PID has exited before removing a stale machine lock.

Every committed learning change carries an `Evidence: <keys>` trailer. Its resolution records the commit and changed paths; an explained no-change decision records its reference and reason. Staged changes remain open. Resolution is tied to the captured occurrence IDs, so an observation appended during learning remains open. A later occurrence reopens a resolved key. `audit.mjs --since <ISO-date>` and weekly maintenance flag recurrence as did not fix and changed pages/skills unobserved since the change as candidates to revert. `hooks.signalLearning.outcomeWeeks` limits the window when configured; otherwise reports cover retained changes. These flags support a review decision, never automatic reversal.

Successful PostToolUse memory-page and SKILL.md reads append `{ts, session, kind, path}` to local `.geppetto/reads.jsonl` with zero model calls. Private pages and failed reads are excluded. The bounded learning file adapter records its own reads through the same logger and grants read access to the exact companion view and bundled guides. Audit compares observed reads with public configured memory pages and installed skills; an unread result means no recorded read in that project/window. Opaque tools, implicit context loading and shell commands without explicit read paths remain outside this path-based observation contract.

## Observability

Learning events retain originating session/turn identifiers, decisions, failures and worktree locations. Per-session cursors identify consumed transcript bytes; source text, transcript slices and private matches stay out of hook-event records. The admission pre-check and reducer use no model calls; provenance checking rereads the local transcript and output validation reads the local private bucket. Background execution uses the configured subscription model and machine lock; blocked and invalid structured assessments preserve pending evidence. Synthetic behavior tests cover reduction, cursor reuse, oversize user text, retries, provider-free admission, cwd-relative reads, junctions, encoded file URIs, Git revision reads, secret redaction, normalized private output in tracked and new files, and public diffs beyond 1.7 MB. The deterministic redactor recognizes the credential formats declared in `signal.mjs`. Shell path extraction is best effort; the output check guarantees rejection of normalized private lines meeting the stated threshold and private paths, while paraphrases without recorded provenance remain outside that contract.
