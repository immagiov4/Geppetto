# Verify

**Local fix.** For a qualified [local fix](../geppetto-spec/references/local-fix.md), run its focused affected-file checks and regressions, inspect the diff and validate PR/ticket Observability, then continue with steps 3–7 below. Load principle skills only for an unresolved concern. Otherwise use the full path.

1. **Choose evidence.** State risk, change type and applicable project rules. A typo may need only a light check and no PR. Use the existing requirements map; read `$requirements-blast-radius` when evidence exposes an uncovered surface or changes the agreed outcome. Complete when the selected verification profile and its reasons are recorded.
2. **Check deterministically.** Run relevant lint, types, tests, static analysis and the project's `.geppetto/bin/gate-sections.mjs`; include feature docs and the instruction gate when affected. Use remote CI when it improves real elapsed time. Read `$geppetto-behaviour-tests` for tier placement and `$geppetto-measure-it` before reporting timing. For installed or modified hooks, complete [hook activation](../geppetto-adopt/assets/templates/hooks/README.md#activation) and verify the final definition in the affected harness and project. Complete when every required result is linked to the current revision or explicitly identified local diff.
3. **Review independently.** Review locally before the PR in fresh context. Provide the diff, authoritative contract and relevant rules, keeping the implementer's rationale out of the material. Separate lenses: specification correctness, quality, project rules and security where applicable. Use the configured reviewer; default to the [bundled code-review procedure](../code-review/SKILL.md) with the available CLI, application or harness selected during adoption. If that runtime is unavailable, inspect the other installed verification tools and use one that provides fresh contexts, separate finding confirmation and retained results. When no independent reviewer is available under current tools or delegation/model restrictions, inspect those lenses yourself, label the result self-review and record `independent review pending` with the reason. Complete when each lens has independent evidence or a reasoned not-applicable result, or the constrained-session handoff explicitly retains that pending gap.
4. **Confirm findings.** Read `$receive-work-feedback` unless adopt explicitly configured its replacement. Validate authority, supported path, consequence and proof separately from discovery. Apply system/API/implementation zoom and the appropriate UX/performance/quality lenses. Decide each finding: fix, reject with evidence, split with authorization, or ask for a named human decision. Complete when every finding has a disposition; a pending decision keeps its affected work open.
5. **Close the class.** Fix at the owner, check supported siblings and rerun affected checks on the updated diff. Later reviews focus on new changes. If repeated rounds fail to converge, narrow or rethink the design; three rounds is an example, not a default policy. Complete when accepted local defects and their relevant siblings are resolved without widening the approved contract.
6. **Deliver evidence.** Verify the actual commit delivered, refresh results after subsequent edits and retain limits of coverage. Obtain human approvals where actual risk requires them. A constrained-session handoff is complete with current-revision checks, labelled self-review, decided findings and the named `independent review pending` gap; required independent review remains open for integration. Complete when claims, checks and approvals refer to the delivered version and every finding has a disposition.
7. **Learn.** Send recurring findings to `$geppetto-learn` for an owning test, lint, rule or skill. Complete when each recurring pattern has a routed signal or an evidence-backed reason to retain the existing rule.

Compare reviewer engines by real defects, false positives, rounds, time, cost and harmful unnecessary fixes through `$geppetto-measure-it`. Read [process execution](../geppetto-adopt/references/processes.md) before tools; honor `$geppetto-authorize` for paid or unattended work.
