# Hook operation

The plugin supplies global hooks. The installer reuses them with `--plugin-hooks`, or merges one shared hook set into user settings. `~/.geppetto/machine.json` records the source. SessionStart injects memory listings and the turn-record command and schema; UserPromptSubmit captures the turn boundary without adding context; PreToolUse gates native file edits and pending shell effects and checks PR text; PostToolUse observes Git changes, re-arms feedback after configured review results and supplies internal learning reminders; Stop checks independent review, then starts background learning through the same dispatch.

## Activation

After installing, changing or curating a hook, synchronize every authorized copy and complete activation of the final definition in each affected harness and project. Finish package refreshes, including a Git-backed plugin cache's revision update, before approving its hashes; a later refresh can invalidate the approval even when hook commands stay the same. An authorized hook change, including a metric-justified improvement already authorized by the user, includes its activation; do not ask for consent again for that completion. A change to permissions or effects beyond the approved change is a separate decision.

- **Codex:** first list definitions with `node <adopt>/scripts/codex-hook-trust.mjs --project <project>` and take the plugin identifier from the returned keys; use that exact identifier with `--plugin <actual-plugin-id>` (or select `--source <hooks-file>` or repeated `--key <key>`). After reviewing the authorized scope, run the scoped command with `--approve`. The helper approves enabled, non-managed hooks in that scope using current hashes and rereads them; inspect its output for disabled hooks, warnings and trust status. A changed payload, command or configuration can invalidate trust. Verify the final hashes and an actual hook event in the same Codex harness and project that will run it; a separate app-server inventory alone is not proof of execution.
- **Claude Code:** settings edits are normally picked up by its file watcher. Confirm the intended hook is enabled and observed in the target session; reload the plugin or start a fresh session if that session has not loaded the final definition. Use the native `/hooks` view and debug output when needed.
- **Hermes:** enable the installed plugin with `hermes plugins enable <name>` in the intended profile, then ensure the serving process has loaded the final version (restart or reload it where required). Verify the hook's effect in that same profile and serving process. A plugin on disk or an enabled flag alone is not proof that its hook is running.

If activation cannot be completed, report the exact blocker and leave the hook's active state unclaimed. Keep changes within the authorized installation and project scope.

## Result attribution

Result records in the repository's shared `hook-events.jsonl` under `<git-common-dir>/geppetto/` (or `.geppetto/` outside Git) include `sessionId` and `turnId` when the triggering harness supplies them. Match these identifiers to the session being investigated before attributing a result: probes and other sessions can write to the same project log. Historical records and events from harnesses without identifiers remain unattributed. The log records selected Geppetto outcomes; native `hook/started` and `hook/completed` events identify failures before a script starts, including Codex plugin-content approval failures.

## Learning

`learn-nudge.mjs` records tool activity and adds one internal reminder per qualifying turn, using the configured tool-count or elapsed-time threshold. The current agent applies `$geppetto-learn` before replying. The handler uses zero model calls; reflection uses the ordinary session. Events record firings and duplicate suppression state stays under ignored `.geppetto/hook-state/`.

The [background runner](../../../../geppetto-learn/references/ingestion.md) receives the new reduced transcript slice and pending signals through the subscription CLI and one machine lock. Stop starts it directly after 20 tool calls or five minutes by default; `hooks.learnNudge` owns those configurable thresholds. [Maintenance jobs](../../../../geppetto-learn/references/jobs.md) reuse the existing scheduler.

PostToolUse also recognizes Write/Edit/MultiEdit and apply_patch paths in Claude's native memory, configured `autoMemoryDirectory` and Codex's `<CODEX_HOME>/memories/`. With bucket memory configured it reminds once per turn to save durable lessons through `$geppetto-memory`; a native directory inside a bucket instead prompts index upkeep. This uses the existing dispatch, an exclusive turn marker and a zero-model-call `nativeMemory` event in the same hook log. Native-only and no-memory choices keep bucket hooks silent. The end-of-turn nudge includes lessons and decision rationale without another owner.

Hermes uses its [plugin template](hermes/plugin.yaml) for read-only memory listings and learning reminders. Copy `settings.example.json` to the profile's `settings.json` and resolve its paths.

## Review gate

`hooks.reviewGate` is enabled by default. Stop blocks once when source changed this turn by at least `threshold` added/deleted lines (default 30), the current diff has no matching independent review, and edits since the latest review also reach that threshold. `docGlobs` and `testGlobs` configure exclusions; defaults exclude Markdown, reStructuredText, docs, tests, fixtures and common test filenames. Prompt or first-tool events capture the turn's initial source state, so pre-existing edits alone do not trigger a block. A second Stop or `stop_hook_active` closes the turn. To explain an unavailable reviewer, state `Independent review blocked: <concrete reason>` in the reply.

Complete `$geppetto-verify` or its configured `code-review` engine to record the reviewed diff. The review record holds a SHA-256, resolved comparison base, timestamp and outcome in shared `reviews.jsonl`, with originating worktree and revision; comparison state under `.geppetto/hook-state/` holds only line hashes. Source and diffs stay out of these files. Tracked and non-ignored untracked text source count; binary files, symlinks and submodule contents are outside this gate's line measure. Review eligibility remains specific to the originating checkout. The gate verifies review identity, while the review procedure owns independence and findings.

Git diff output streams into the fingerprint, including patches larger than 1 MiB. Collected Git text output, including repository inventories, has no fixed subprocess buffer limit; callers can set an explicit `maxBuffer`. These reads retain their output in memory. Any PreToolUse or PostToolUse error allows the tool and emits one redacted diagnostic line on stderr. Any Stop error lets the turn close and records one redacted error per session/turn in `hook-events.jsonl`; an active Stop also closes. Manual recording commands retain their error exit codes. If the diagnostic itself cannot be persisted, stderr retains its cause.

## Turn record

Before the first file-modifying tool call, record the configured decisions with `node <adopt>/scripts/hook.mjs --record-turn '<json>' --session <session-id>` from the project root. SessionStart supplies the resolved command, questions, skills and minimal schema once per session. Edit-free turns need no record. An explicit `--turn <turn-id>` checks the identity; `--record-turn -` reads JSON from stdin. If the current decision is missing, PreToolUse denies one editing call with the command and schema; repeated attempts pass to avoid a denial loop. Stop retains only the independent-review gate above.

Write/Edit/MultiEdit, namespaced apply_patch and MCP file-writing tools receive the preventive check. Shell commands run freely. At each PostToolUse, Git porcelain status and changed-path size, modification time and change time are compared with the turn's initial fingerprint, then with the last observed fingerprint. A change without a current decision requests the record at the next tool call, even a read; the first shell edit can precede the request. This observes tracked, staged and non-ignored untracked changes, including changes to already-dirty files. Git-ignored files and Geppetto's runtime ignore file are outside this observation. The edited-turn metric counts admitted native edit attempts and observed Git changes; a failed native tool can still leave no changed bytes.

`.geppetto/config.json` accepts `turnChecks` as an array of `{id, question, skill}`. To configure review-result matching, use `{ "checks": [...], "rearmOn": [...] }`; omitted members inherit the bundled defaults in `scripts/turn-checks.json`. Installation and audit validate the definitions. An empty checks array disables decision requests. SessionStart and validation derive from the same list. Built-in IDs retain the schema below; other IDs use `{ "applies": false }` and require a meaningful one-line `reason` when true.

```json
{"requirements":{"changes":false},"feedback":{"applies":false},"frustration":{"applies":false}}
```

Use `requirements.changes: true` when the user changes even one agreed point; run `$requirements-blast-radius` against the original request and agreed changes, and put the changed point in `what`. For feedback from the user, a reviewer, CI or a delegated agent, run `$receive-work-feedback` and record `feedback.applies: true`, `on` (what the user judged) and `action` (what you did). For frustration caused by your work, use `$geppetto-learn` and record `frustration.applies: true`, `cause` and `prevention` (the owning improvement or signal). Each positive reason is a meaningful single line; placeholders such as `n/a`, `none`, `-`, `ok` and `no` are rejected. Keep reasons concise and free of secrets. For a pure continuation with no user message content to judge, use `{"continuation":true}`. The gate checks the record's structure; the agent owns the judgments and actions.

`rearmOn` rules match `tool` against the tool name without its namespace. A `gh` rule names the subcommand, with optional `path` regex for its first positional argument and `flags` for required options; for example, `{ "tool": "^Bash$", "gh": "pr view", "flags": ["--comments"] }`. Parsing separates positional arguments from options and their values, including repository, header and method options. A `script` regex matches the Python script path on a real run. A `command` regex supports custom command matching; a tool-only rule matches any result from that tool. Help invocations preserve the decision. Defaults cover gh api pull comments/reviews, gh pr view --comments, gh pr checks, the bundled Python code-review script, delegated-result tools and gh run view --log-failed. Unrelated calls preserve the decision; tool-use IDs suppress duplicate result delivery. The next edit requests feedback again, preserving other decisions. A feedback-only record is accepted after a prior decision; continuation cannot bypass renewal. Output text is not classified.

The command stages validated decisions under ignored `.geppetto/hook-state/`; concurrent sessions remain separate. Incompatible active state starts a fresh current turn. Closing Stop appends one line to shared `turns.jsonl`, with gate-computed review metadata, identities, timestamps and transcript byte boundary. Each decision in `decisions` retains its value, `requestedAt` and `decidedAt`; their nonnegative waits sum to `addedSeconds`. A proactive decision before any edit request has zero wait. Re-recording the same decision cycle replaces its observation. Optional `userCorrection: true|false` explicitly classifies whether this user message corrects the immediately preceding work; leave it absent when unknown. A pure continuation remains eligible for that declaration.

## Observability

`hook-events.jsonl` records reviewGate outcomes, changed-line counts and current diff hash, turnGate block/rearmed/recorded outcomes, startup context bytes, completion errors and learning events. `turns.jsonl` retains the agent's decisions and wait durations for calibration. `audit` reports median added seconds per recorded admitted edited turn, corrections among classified immediate next messages in the same session, and the unknown count. Edit-free messages without a voluntary classification and legacy records remain unclassified; this is an observed sample, not an inferred correction rate. Turns that close without a record are outside the timing sample. The gate uses zero model calls. Its benefit is a decision before editing; startup context, local Git reads and decision recording add interaction cost. Synthetic tests cover config-driven decisions, placeholders, re-arm matching, continuations, isolation, concurrent delivery, error recovery, measurement and review identity. Real Claude and Codex sessions verify edited and edit-free turns separately. Background admission, cursor and reducer limits belong to the linked learning lifecycle.
