# Learning in the working turn

When the maintainer expresses frustration caused by the work, the current agent applies `$geppetto-learn` and records exactly one outcome through `hook.mjs --record-turn` with a `learning` object. `lesson` names a project-relative file changed during this user turn; `covered` names an existing rule file; `one-off` explains why the case will not recur; `blocked` names an inaccessible owner, a reason and a slug key. All outcomes require a meaningful one-line reason. An installed plugin or another repository's rule is retained in the project's instruction file instead. Plain steering requires no outcome.

The hook hashes tracked and nonignored files at the user-message boundary. Stop compares the lesson owner's content with that baseline, including instruction files excluded from code review. A missing frustration outcome or unchanged lesson owner blocks once per user message and supplies the recording command. A subsequent Stop may end; unresolved failures remain visible. A check error lets Stop end and records a completion error. New user messages clear the prior outcome; resumed native turns retain separate state.

`signal.mjs --list` returns only open key IDs. Recording requires a short key, session and one category from project `categories`; `other` requires concrete evidence. Ordered category objects carry `id`, a one-line definition and `score` (the observation method). Assignment uses the configured order, with one primary category per episode and secondary effects in `attributes`. The shipped order is security, verification, workflow, efficiency, communication and behavior. Legacy records retain their metric fields without a guessed mapping. A key counts once per distinct session. User provenance comes from the first decision of the active turn or its completed feedback/frustration record; an unflagged observation is agent-sourced. An explicit user-source claim requires those flags. Use --source agent for an agent-discovered observation even during a flagged user turn.

Runtime records live in `geppetto/` under the absolute directory returned by `git rev-parse --git-common-dir`, shared by the main checkout and its linked worktrees. Projects outside Git retain `.geppetto/` storage. `signals.jsonl` is the append-only evidence archive. Occurrences carry `key`, `source`, `category`, `session` and open status; resolution events add a reference, reason and changed paths. Merges retain `merged-into:<key>` and combine distinct session identities at the destination. The curator proposes a new class only from at least three evidenced other keys across sessions, retaining definition, score method and rationale in `category-proposals.jsonl` in that shared directory for the maintainer's decision. Config replaces the category list without code changes.

Geppetto preserves legacy journals as immutable imports under the shared `legacy/` directory. Records retain their originating worktree and revision; hook state remains checkout-local. Existing learning branches and working directories remain available for inspection.

Agent evidence qualifies at `hooks.signalLearning.minSessions` (default 2); the existing `maxOpenKeys` threshold also offers open evidence. User-sourced signals qualify immediately. The next tool result presents eligible keys to the working session without starting a model; Stop cannot carry that context in Codex or Claude Code. Include `key` in the learning outcome to resolve that occurrence; blocked appends an open signal automatically. A later occurrence reopens a resolved key. Weekly curation merges duplicate keys and prunes procedures; the current working session applies lessons.

Close historical evidence by hand with `node <adopt>/scripts/signal.mjs --close <key> --reference <commit-or-PR> --reason "<verified disposition>"`. The reference and reason are retained, and resolution is tied to the latest observed occurrence ID. The key must be open.

Successful PostToolUse memory-page and skill reads append path-only observations to `reads.jsonl`. `audit.mjs --since <ISO-date>` reports recurrence and changed pages without subsequent recorded reads. These are observations for human judgment. Weekly subscription jobs retain file-only tools and their own output logs.

On installation or update, the installer removes the obsolete machine `learn.lock` and `integrations.md.*.tmp` files. Existing learning branches and worktree directories remain intact.

## Observability

`learningOutcome` in shared `hook-events.jsonl` records outcome, path or reason, optional key, session/turn and user-message epoch with zero model calls. `learningGate` records an unresolved outcome and whether this Stop blocked or was a repeated Stop. Completion errors retain the diagnostic cause and allow termination. Inspect `signals.jsonl` for blocked evidence, manual references, resolutions and recurrences. File digests stay in checkout-local hook state; source contents stay out of event logs. These events establish recording and mechanical file changes; the lesson's relevance is judged from the actual session and owner.
